# v2.4.1 — 自带宿主桥自愈

发布日期：2026-11-10
适配宿主：Twilight Echo 2.0.0 / 2.0.1（官方安装器重发构建同样适用）

## 这个版本解决什么

Twilight Echo 每次官方升级都会整体覆盖 `resources/app.asar`：

- 宿主自带 `out/renderer/we-background.js` 退回 v5（没有轮播、播放页背景不完整）；
- `index.html` 里注入的 `<script>` 入口被清掉；
- meta CSP 与主进程 CSP 里的 `127.0.0.1:3100` 被清掉。

以前只能手动重跑 `bridge/install.mjs`（还要求本机装 Node + `@electron/asar`）。
2.4.1 起插件自己发现、自己修。

## 变更

### 新增 `lib/bridge-adapt.mjs` + `lib/asar-lite.cjs`

自带 asar 读写（Chromium Pickle 格式），**不依赖 @electron/asar、不需要 npm install**。
只打壁纸需要的三处补丁，不碰下载插件的东西：

| 补丁点 | 内容 |
| --- | --- |
| `out/renderer/we-background.js` | 宿主 v5 → v9（`BRIDGE_VERSION = 9`） |
| `out/renderer/index.html` | 加 `<script type="module" src="./we-background.js">` + CSP 放行 `http://127.0.0.1:3100` |
| `out/main/index.js` | 响应头 CSP 追加 `http://127.0.0.1:3100` |

- 备份：`app.asar.te-we-backup-<版本>`，并同步维护 `app.asar.te-we-backup`；
  同版本号重发安装包时会比对内容后刷新，避免把旧构建当原包。
- 写入：临时文件 + `rename` 原子替换；写前 `vm` 编译校验，写后回读校验桥版本 / 入口 / CSP。
- 失败即停：回读不过就不替换原包。

### 插件自愈

`index.mjs` 激活 2.5 秒后只做**只读检查**；桥缺失或低于 v9 时，用 Twilight Echo 自带的
`resources/core-node/runtime/node.exe` 拉起 `bridge-adapt.mjs --wait-exit`，
等应用退出后自动重打，并只提示一次。日志：

```text
%APPDATA%\TwilightEcho\plugin-data\com.twilightecho.tool.wallpaper-engine\bridge-adapt.log
```

### 手动入口

- 双击 `add-bridge.cmd`（用 TW 自带 node，无需安装 Node）；
- 或 `node lib/bridge-adapt.mjs [--app DIR] [--dry-run] [--revert] [--force] [--auto] [--wait-exit]`。

完整教学：[`docs/HOST-BRIDGE.md`](../HOST-BRIDGE.md)。

## 附带文件

发布包（`.tep`）与仓库都附带渲染桥本身：

```text
bridge/we-background.js     ← 仓库里的源文件（v9）
patch/we-background.js      ← .tep 包内的副本，安装后插件按它打补丁
```

## 实测

- 把 `app.asar` 还原成官方原始包后，只跑 `lib/bridge-adapt.mjs`：桥 v9 / 入口 / CSP 全部恢复，
  下载插件的 `te-dl.js` 未被误改；
- 再启动应用，日志显示 `[bridge-adapt] 宿主桥 v9 正常`，没有重复排队；
- 轮播复测：切页触发 `page` 切换一次（第二次被冷却正确拦截）；定时触发 1 分钟后自动切换；
  测试后配置与壁纸已还原。

## 升级方式

1. 完全退出 Twilight Echo；
2. 用插件管理安装 `com.twilightecho.tool.wallpaper-engine-2.4.1.tep`（覆盖旧版）；
3. 启动一次、再退出即可自动重打桥；或双击 `add-bridge.cmd` 立即打。

## 已知边界

- 自动重打发生在应用退出后；升级当次会话里背景仍可能是旧的，退出一次即恢复。
- 切页轮播仍依赖宿主导航的 `.menu-item[aria-current="page"]` + `data-page-id`；
  宿主若改导航结构，需要同步校准 `pageSignature()`。
